The decisions

Constraints create character.

A good specification records what we chose. A useful decision journal also records what we rejected, what risk the choice creates, and what evidence could change our minds.

Product / active MVP

Four players share one dangerous map.

The active MVP is a continuous two-to-four-player free-for-all, designed and tested primarily with four. Every player and server-controlled creature inhabits the same map from “Go,” and the last survivor wins.

Why: four players introduce third-party threats, conflicting routes, and shifting pressure while remaining small enough to understand, test, host, and balance without rebuilding the sixteen-player pack system.

Gameplay / continuity

No timer decides when rivalry starts.

PvP is legal from the opening second. Opposite concealed spawns, multiple routes, creatures, central loot, and closing darkness shape when players meet without a preparation barrier or teleport.

Why: a scheduled final duel made the match feel like two disconnected games. Continuous rules let luck, information, route choice, and aggression produce the confrontation.

Technical / stack

Three.js in front, Colyseus in charge.

The browser uses TypeScript, Vite, Three.js, and a small React shell. Node and Colyseus own movement legality, creatures, ammunition, reloads, hits, pickups, darkness, death, and victory.

Why: Death Race already proved this deployment and room architecture for the team. Reusing its lessons keeps one language across the stack while the server protects the human-versus-human result.

Process / delivery

Every task closes the whole loop.

The active implementation plan gives each LLM task prerequisites, bounded deliverables, acceptance checks, exclusions, and the same finish line: update this journal, test, commit, push, deploy, and verify.

Why: small code changes still fail at integration and deployment boundaries. Requiring a complete closeout keeps the repository, hosted game, documentation, and learning record aligned after every step.

T0.1 / repository boundary

The web game starts beside the Godot experiment.

The outer repository is the one application root. The untracked Godot project stays in place as user-owned source, its .godot folder remains generated cache, and the nested folder remains reserved for conversation attachments. Death Race is a reference, never a source donor.

Why: migration work is safest when ownership is explicit. Building beside the experiment lets us learn from it without deleting history, accidentally committing generated files, or hiding the real project inside another folder.

T0.2 / foundation

One workspace, three visible boundaries.

A single pinned pnpm project now contains a Vite and React client, a Node and Colyseus server, and a framework-neutral shared layer. Strict TypeScript, Vitest, Oxlint, Prettier, production building, and an automated cross-import check form the first quality gate.

Why: a monorepo manager would add another concept before it solves a real problem. Plain folders make authority easy to see: the browser presents, the server decides, and shared code knows about neither UI nor transport.

T0.3 / configuration

Local defaults are friendly; hosted mistakes are loud.

Development runs without credentials, while staging and production require a public secure game endpoint, explicit browser origins, and identifiable health metadata. Both configuration parsers accept injected values and report the exact invalid setting.

Why: environment bugs often survive a local demo and only appear after release. A production browser silently connecting to localhost is especially confusing, so the safest default is to stop early and explain what the deploy is missing.

T0.5 / server identity

The first authority is identity, not movement.

A versioned Colyseus room now accepts four clients, cleans their display names, assigns server-owned UUIDs, publishes a tiny waiting-room schema, rejects incompatible protocols, and disposes itself when empty. Health and lifecycle events carry searchable release metadata.

Why: identity is the smallest consequential fact worth protecting. Proving it before movement exposes room limits, schema compatibility, failed joins, and cleanup behavior without hiding those lessons beneath gameplay code. Current schema() definitions also replace the legacy metadata API that failed under the pinned TypeScript runtime.

T0.4 / first pixels

One scene owner, one supported browser.

An orthographic Three.js world now renders a ground plane, obstacle, and upright dog marker beneath a separate React title layer. It preserves world scale while resizing, caps pixel density for web performance, respects reduced motion, and explicitly releases every frame callback and GPU resource.

Why: scene ownership is easier to learn when creation and disposal live in one class. Chrome is the sole MVP browser because cross-browser certification was blocking core-game progress without testing the product hypothesis; broader support can be earned after the loop is fun.

T0.6 / first synchronization

Copy network truth before drawing it.

Chrome now joins the real Colyseus room, shows the identity assigned by the server, and renders one dog placeholder per stable player ID. A small transport owns connection states and cleanup; an adapter turns live schema objects into sorted, frozen view records before React or Three.js receives them.

Why: synchronized objects are live server state, not convenient UI models. Copying at the boundary prevents a renderer from accidentally changing network truth, makes state updates testable without a canvas, and lets the scene reconcile objects by identity instead of rebuilding everything. Generation checks also close connections that finish after a page teardown, avoiding the classic refresh leak.

T0.7 / hosted baseline

Static pixels and live authority deploy separately.

The browser ships to Cloudflare Pages while a small Node container runs Colyseus on Fly.io in Sydney. Releases pin the WSS endpoint at build time, expose a versioned health check, run a real hosted join smoke, and document rollback for each artifact.

Why: static files and long-lived WebSockets have different hosting needs and failure modes. The first smoke test also exposed why the server must remain one machine today: in-memory matchmaking placed an HTTP reservation on one machine and the socket on another. Explicitly disabling high availability is safer than pretending the current room server can scale; shared presence can be added only when real load earns that complexity.

Phase 0 gate / passed

Intent goes in; truth comes back.

The foundation now has one explainable authority path: browser controls become versioned commands sent to a room; the room validates and changes schema state; Colyseus synchronizes it; an immutable adapter feeds React and Three.js. Client and server then release and roll back independently.

Why: multiplayer bugs become much easier to reason about when every fact has one owner and every boundary has one direction. Proving that path locally and over hosted WSS before adding movement means later gameplay failures can be isolated to commands, simulation, synchronization, or presentation instead of an unknown deployment foundation.

T1.1 / numeric contract

The world runs on metres and ticks.

Simulation uses a flat X/Z plane, radians for direction, immutable conversion into Three.js X/Y/Z, and integer ticks at a fixed 30 Hz. Shared guards reject non-finite and out-of-bounds values, while seeded randomness makes later spawn choices exactly repeatable in tests.

Why: render frames speed up, slow down, and disappear in background tabs; they cannot be the game clock. One fixed step makes movement and combat reproducible on server, client, and test runner. Explicit coordinate conversion also prevents the common mistake where simulation Y means “forward” but Three.js Y means “up,” and rejecting NaN early prevents one malformed command from poisoning an entire room.

T1.2 / command contract

Players send verbs, never results.

A strict, versioned envelope now carries twelve permitted intentions with room, match, and sequence identity. Payloads contain only what the player did—movement axes, aim angle, or readiness—while exact-key validation rejects hidden extras, claimed damage, duplicate order, stale matches, and malformed numbers.

Why: “I fired” is a legitimate request; “I dealt 50 damage to that player” is not. Keeping outcomes impossible to express makes server authority a property of the protocol instead of a convention developers must remember. Strictly increasing sequence numbers also turn retries and reordered packets into harmless, explainable errors before simulation begins.

T1.3 / Red Hollow

One map, two routes, no opening shot.

Red Hollow places four named spawns behind perimeter screens, gives each two verified paths inward, and surrounds a covered centre with entries from every side. The server reads simple collision boxes while Three.js derives capped visual ruins from those exact same records.

Why: a handcrafted arena lets early playtests ask whether routes and information are interesting instead of whether a generator happened to be kind. Blocking every initial sightline prevents a loading-screen death, while paired paths preserve agency. Keeping decorative geometry derived from collision data gives the client character without letting an invisible server wall drift away from what players see.

T1.4 / server movement

The room moves every dog.

Players supply a normalized direction; the server owns position, six-metre-per-second speed, collision radius, fixed-step integration, map bounds, obstacle response, and sequence acknowledgement. Thirty simulation steps occur per second no matter how Node timer callbacks are partitioned.

Why: accepting a client position would make speed limits and walls suggestions. Keeping only input on the wire lets one deterministic simulation decide where every dog can be. Axis-separated circle collision is intentionally modest: it supports sliding and the authored boxes without introducing a physics engine before combat proves one is needed.

T1.5 / synchronized presentation

Snapshots move remote dogs, not React.

A renderer-owned registry creates one object per server UUID, buffers authoritative positions, interpolates remote dogs 100 milliseconds behind real time, follows the local dog with the camera, and disposes departures exactly once. React hands over snapshots but never touches per-frame transforms.

Why: network patches arrive in steps while displays redraw much faster. Interpolating between timestamped truth makes remote motion smooth without guessing where an opponent will go. Keeping that work inside Three.js avoids rerendering the component tree sixty times a second and gives every GPU object one obvious lifecycle owner.

T4.1 / creature foundation

Creatures begin as lifecycle, not personality.

A room-owned registry now creates, queries, advances, damages, kills, despawns, and clears synchronized creatures alongside their runtime records. It owns a hard cap of 48 and accepts a target-selection policy while the existing 30 Hz simulation owns time. Creature coordinates use the same revocable view channel as hidden opponents.

Why: building “swarmer” directly into the room would mix storage, pacing, AI, combat, and presentation before any boundary was testable. The neutral registry makes leaked entities and unbounded populations structurally difficult, gives later creature types one authority path, and keeps Three.js entirely downstream of server truth.

T4.2 / swarmer

Pressure announces itself before it bites.

The swarmer pursues the nearest living dog, separates from its group, follows walls around authored cover, and stops to pulse through a 400-millisecond contact warning. Damage occurs only if range and sightline are still valid when that warning ends; pistol and melee can interrupt it through the shared creature health and death path.

Why: a fast enemy is only fair when its danger is readable. Rechecking at impact makes the warning a real dodge window rather than decoration. Deterministic wall-follow state avoids an expensive navigation mesh for seven authored boxes, while separation prevents a visually merged stack from pinning a dog. Actual spawn zones stay out of this task so behaviour can be proved before pacing multiplies it.

T4.6 / centre shotgun

Seven pellets make the middle worth contesting.

One seeded central pickup replaces the pistol with a four-shell shotgun. Seven authoritative rays form a short, fixed fan; cover blocks each pellet independently, concentrated hits kick targets back, and the slower fire/reload cycle plus sixteen-shell reserve ceiling limit repeated pressure.

Why: the shotgun is spatial leverage, not a numerical promotion. Its range forces commitment and its small magazine creates punishable downtime. Swapping one found weapon writes the old weapon and exact ammunition back into the same pickup entity, so ownership moves between world and dog without a duplication path or an inventory screen.

T4.4 / authored pressure

Every corner pays the same entrance fee.

Four regional zones now contribute four seeded creatures each to a normal match: three swarmers and one spitter per region. Their 48 validated points also define the stress ceiling. A five-metre player exclusion can reduce population but can never be bypassed to satisfy a number.

Why: unconstrained random spawning can decide a match before players make a choice. Equal regional quotas make opening pressure comparable, while seeded point selection preserves variation and reproducibility. Reusing the authored 48 points for the hard-cap test connects performance evidence to the actual map instead of a synthetic benchmark.

T4.3 / spitter

Ranged pressure travels through time and space.

A fragile spitter holds medium range, warns for 650 milliseconds, and only then launches a capped server-owned projectile. The shot has visible travel time, collides with authored cover, can be sidestepped, expires after 2.2 seconds, and never homes. Range and sightline are checked before and after wind-up.

Why: applying delayed damage directly would make the warning cosmetic and dodging ambiguous. A real projectile turns the telegraph into a readable movement problem. Keeping its thirteen-metre attack limit inside the sixteen-metre visibility radius means a hidden spitter cannot legally create an unseen attack, while a 64-shot cap and explicit collision/expiry keep server and browser cost bounded.

Phase 3 gate / passed

Six hosted matches closed the room loop.

Two consecutive matches at each supported size—two, three, and four dogs—ran over Sydney WSS with injected latency and jitter. Every client began with private coordinates, observed legal reveals, agreed on one combat winner, returned through host rematch, disconnected, and created a fresh room without stale state.

Why: four-player remains the primary case, but auto-sized friend rooms must not depend on a full lobby. Using the identical public-command harness across all sizes proves that countdown, visibility, last-dog-standing, host ownership, rematch, and cleanup are properties of the room model—not happy accidents of one population.

T1.6 / prediction

Immediate to you, authoritative to everyone.

WASD predicts one fixed movement step immediately and records it by sequence. Each server snapshot discards acknowledged inputs, resets to authoritative position, and replays the remainder. Small drift settles quietly, ordinary drift blends, and errors above two metres snap safely to truth.

Why: waiting a full network round trip makes correct movement feel broken. Prediction removes that wait without granting authority because no predicted position is sent or shown to opponents. Reusing the same collision integrator reduces ordinary disagreement, while explicit soft and hard thresholds make correction behaviour testable under 150 milliseconds of latency and jitter instead of tuning it by hope.

T1.7 / dash

Space asks; the room decides.

A dash covers 4.5 metres over six fixed ticks, respects the same walls and bounds as walking, pauses movement briefly afterward, and cannot begin again during its 1.2-second cooldown. Clients predict the motion and squash the dog immediately, while a server event confirms legal dashes to everyone.

Why: dash should feel like a sharp movement verb, not a loophole through geometry or cooldown. Sharing collision and replay logic keeps it responsive under latency without accepting a client-authored destination. A monotonic event counter gives presentation something distinct to celebrate while remaining evidence of a server decision; no invulnerability was smuggled into the mechanic.

Phase 1 gate / passed

Four views, one movement truth.

Four hosted Chrome tabs received unique identities and corner spawns while rendering the same four dogs. A separate real-WSS harness moved and dashed every client, observed four accepted dash events, and compared all final positions; the 150-millisecond jitter harness remained green beside it.

Why: prediction and interpolation are deliberately different. Prediction lets your own intent appear before the server answers, then reconciles it; interpolation delays someone else slightly so two known server snapshots can be blended smoothly. Neither changes the shared truth. Testing four browser presentations plus four command-producing clients proves those paths converge under both controlled and real hosted latency.

T2.1 / combat foundation

Every wound travels one road.

The first firearm is a validated, immutable data definition covering damage, cadence, ammunition, range, spread, knockback, and active-reload timing. Firearms, melee, creatures, and darkness all feed ordered damage events into the same authoritative resolver.

Why: combat values hidden inside rendering code are difficult to balance and impossible for the server to defend. A data boundary makes bad or contradictory tuning fail during development. One deterministic damage queue also prevents later systems from inventing their own health rules, while event IDs and explicit ordering make duplicate and simultaneous attacks testable.

T2.2 / authoritative firearm

The click is a request, not a hit.

The pointer sends a throttled aim angle and the primary button sends an ordered fire intent. The room owns the eight-round magazine, reserve count, 240-millisecond cadence, range, authored-wall ray tests, player intersections, dry fire, and the final shot endpoint synchronized for presentation.

Why: sending a claimed victim would let a modified browser shoot through walls or across the map. Reconstructing the ray from server position and last accepted aim makes ammunition and cover enforceable. A compact shot counter and endpoint tell every renderer what happened without exposing mutable combat authority or requiring React to animate it.

T2.3 / active reload

Reload safely, or gamble on X.

R begins a committed 1.5-second reload. Doing nothing always completes it normally; pressing X once can produce a faster good reload, an immediate perfect reload, or a two-second fumble. The client submits elapsed input time—not an outcome—and the server reconciles it against its own clock with at most 150 milliseconds of compensation.

Why: the safest option must remain dependable while the timing input creates a meaningful combat risk. Bounded compensation keeps the mechanic playable over real latency without letting a browser claim “perfect.” A labelled bar near the action uses shape, motion, and words as well as colour, and committed reloads block firing so failure cannot be cancelled for free.

T2.4 / fallback melee

An empty gun is not helpless.

Right-click commits a short forward strike with a 100-degree arc, 2.1-metre reach, 100-millisecond wind-up, and 450-millisecond recovery. The room chooses the nearest visible target, blocks strikes through cover, applies collision-safe knockback, and publishes one presentation event.

Why: limited ammunition needs a dependable fallback, but infinite melee cannot become a rapid stun loop. Wind-up makes spacing readable and recovery preserves a chance to answer. Capturing server aim at commitment prevents a last instant browser correction, while reload lockout makes a fumble a real consequence instead of something melee can cancel.

T2.5 / health and elimination

The whole tick gets its say.

Every dog starts with 100 server-owned health. Firearm and melee hits enter one ordered damage queue, then the room resolves the complete simulation step before eliminating anyone. Zero health immediately stops movement and combat input, flattens the dog in the renderer, and records one killer and one elimination event.

Why: resolving one network message all the way to death before considering the next would make equal attacks depend on callback order. Batching a fixed step permits fair, deterministic mutual kills while preserving exactly-once death. Health still changes through the shared resolver, so later creatures and darkness cannot quietly invent different damage rules.

T2.6 / combat feedback

Punch is loud, brief, and disposable.

Server shot counters produce short tracers, muzzle and impact flashes, recoil shake, hit pulses, restrained local hit-stop, death posture, and named audio-hook events. Shooter hit, miss, dry fire, victim hit, death, melee, reload grades, and fumble all have distinct presentation cues. The server keeps completed reload grades labelled for 700 milliseconds of simulation time so an immediate perfect result is still readable without a racing browser timer.

Why: authority can be strict without combat feeling delayed. Feedback celebrates an observed server result but never creates one. Transient GPU objects expire in the render loop, are capped at 32, and dispose their geometry and materials; no effect owns a timer. Reduced-motion or ?effects=low removes shake, flashes, and hit-stop while retaining the tracer and labelled reload telegraph needed to understand play.

Phase 2 gate / passed

Ninety seconds proved more than connection.

Four hosted WSS clients produced 72 shots, 21 reload transitions, 133 melee resolutions, 19 observed damage changes, and three eliminations during the required ninety-second combat run. A separate Chrome check exercised the deployed presentation and its accessible reload labels.

Why: a combat gate must observe the whole path, not merely join four sockets. The visual pass caught a perfect reload label racing against client patch timing even though all mechanics and tests were green. Moving the brief result lifetime into synchronized simulation ticks made the cue deterministic and demonstrated the value of testing what a player sees as well as what the server counts.

T3.1 / private lobby

Six characters gather the friends.

A player creates a private room, shares a six-character code, and becomes host. Two to four sanitized names appear in a ready roster; every connected dog must be ready and only the current host can start. Leaving transfers host and clears stale readiness.

Why: friend games need a code, not accounts or public matchmaking. A small in-memory registry on the existing single server resolves the friendly code to Colyseus's real room ID and distinguishes invalid, missing, full, and already-started rooms. It adds no database and cleans itself when the room dies; if hosting later scales beyond one process, this deliberately narrow registry is the boundary to replace.

T3.2 / concealed spawns

The roster is public; the corners are not.

At start, a seeded allocator scores every valid subset and gives two to four players unique, maximally separated authored spawn regions. Four players use every corner; two use opposite corners; ties and player assignment are deterministic for the match seed.

Why: fairness needs authored distance, while replayable tests need a seed. Colyseus schema views keep names and readiness public but grant spawn ID and exact coordinates only to the owning client. The server still holds the full map; later visibility work can deliberately add an opponent to a viewer rather than trying to retract coordinates already leaked.

T3.3 / match lifecycle

“Go” is a server boundary.

The room owns lobby, three-second countdown, playing, round-over, and closed phases. Starting locks new seats, increments the round, generates a fresh match ID, assigns spawns, and ignores movement or combat until countdown reaches zero.

Why: a client-side countdown is decoration, not a rule. Binding every post-start command to the server-generated match ID makes delayed packets from the lobby or an older round fail before ordering or simulation. Unlocking only during a deliberate lobby reset keeps late joins from reserving a seat midway through the fight.

T3.4 / last dog standing

One survivor, or none.

After each fixed-step damage batch, the room counts living dogs. One produces a named winner; zero produces a draw. The result is emitted exactly once, combat stops in round-over, and only the host can return everyone to the private lobby for a clean rematch.

Why: checking victory inside an individual hit would break simultaneous deaths. Evaluating after the complete damage batch preserves mutual-kill draws and makes two-, three-, and four-player elimination order irrelevant. Rematch keeps social continuity but restores health, ammunition, movement, reload, melee, elimination, readiness, and spawn state rather than carrying invisible debris into the next round.

T3.5 / private sightlines

Hidden means absent, not transparent.

Every connection now has its own position view. An opponent's exact coordinates appear only while that living dog is within 16 metres and an authored obstacle does not cross the sightline; stepping behind cover or out of range removes those fields again. The public roster remains available, while spawn assignment stays on a separate owner-only channel.

Why: Three.js cannot protect information it already received. Separate Colyseus view tags let the server revoke position without accidentally revealing the private spawn field. The range is an input to one shared rule, giving later darkness a clean way to contract vision. Gunfire does not override exact visibility yet; a future sound cue may disclose an approximate direction without leaking a hidden coordinate.

T3.6 / disconnect forfeit

Leaving the hunt means leaving the round.

A disconnect during countdown or combat now forfeits immediately. The server revokes input authority, stops active actions, marks the dog eliminated with a visible disconnect event, transfers host when needed, and reevaluates the winner. The record remains for the result, then disappears when the connected host returns the survivors to the lobby.

Why: a reconnect grace timer adds paused or immortal bodies, delayed victory, session restoration, and another class of timers before we know the five-minute game is fun. Immediate forfeit is severe but predictable for a friends-first browser MVP. It behaves identically with two, three, or four dogs and cannot stall last-dog-standing.

T3.7 / four-client harness

The whole round is now one repeatable test.

Four real SDK clients create and join one private room, assert their distinct hidden-state perspectives, ready, traverse the authored routes, reveal opponents, fight to a shared winner, rematch, leave, and repeat. A seed plus optional latency and jitter make the same run reproducible locally or over hosted WSS.

Why: isolated mechanic tests cannot prove that room locks, match IDs, visibility views, combat, victory, and rematch compose correctly. Driving only public client commands keeps this gate honest. It immediately found eliminated bodies still participating in later attack traces, so dead dogs are now excluded before firearm and melee targeting rather than becoming invisible shields.

T4.5 / finite supplies

One key, one claimant, one disappearing box.

Twelve seeded supplies now occupy authored route and conflict points: eight ammo boxes and four small heals. Pressing E within 1.6 metres asks the server to consume the nearest visible eligible item immediately. Health and reserve ammunition are capped, and supplies do not respawn.

Why: an explicit interaction preserves the risk of stopping near a resource without requiring a hold bar in a deliberately sparse HUD. The room serializes simultaneous claims and deletes before another command can benefit, making duplication impossible. Refusing consumption at a stat cap prevents one player from accidentally denying a useful item to everyone else.

Process / first product

The solo study remains, but it is not the build.

The solo specification is preserved as a record of scope reduction. The active build restores only the smallest server-backed feature that matters: one unpredictable human opponent.

Why: pure solo would simplify learning, but it could not test whether the encounter with another player is the memorable payoff. Two players are the minimum honest experiment.

World / production

Chunky 2.5D without an art pipeline trap.

Three.js uses an orthographic camera, low-resolution rendering, sprite or billboard characters, and simple geometry for depth and sightlines. Strict isometric tiles and frame-heavy animation remain out.

Why: this preserves the compact pixel character while allowing simple browser-native geometry, occlusion, camera control, and effects without requiring a full model-and-rig workflow.

Archived / sixteen-player vision

Sixteen dogs, packs of four.

Players are assigned randomly to balanced packs. No pack exceeds four dogs, and packs cannot be hand-picked.

Why: twenty people were too difficult to coordinate and read. Four is intimate enough for rescues and equipment sharing while still allowing four rival groups.

Gameplay / match

No safe preparation phase.

PvP and PvE are active immediately. Packs begin far apart, then better loot and closing darkness pull them inward.

Why: teleporting into a final arena broke the journey. Early encounters should be lucky, skilful, disastrous, and memorable.

Archived / expanded roster

Dogs, not classes.

Every dog begins with equal health, speed, armour, regeneration, dash, and revive capability. Each has one starting weapon and one unique ability.

Why: rigid tank/healer/damage labels make friends negotiate a composition before they have fun. Feats and loot should create the build during play.

Archived / pack leadership

Alpha is honour, not power.

Every pack begins with a random alpha. Leadership changes through broad recent contribution, and total alpha time becomes a score.

Why: a powerful alpha would snowball or invite abuse. Prestige celebrates helpful play without deciding who receives loot or who wins a fight.

Archived / pack revival

You can always rescue the pack.

Dogs go down and may crawl. Enemies cannot finish them. Any standing packmate can revive them; the pack loses only when everyone is down.

Why: revival turns proximity into action. It produces last stands and rescues without asking eliminated players to wait through most of a match.

Archived / build system

One weapon. One armour. One relic.

No inventory grid and no loot vote. Drop what you have; another dog can pick it up. Only weapons drop when a whole enemy pack is eliminated.

Why: physical exchange keeps cooperation inside the world. Three slots make every object legible and every hand-off consequential.

Gameplay / skill

Reloading asks a question.

Ignore the timing line for a normal reload, hit the window for speed, land the perfect mark for near-instant recovery, or mistime it and fumble.

Why: limited ammunition should create skill and tension rather than downtime. Choosing to attempt the input is itself a tactical risk.

Archived / compass rule

The compass is the HUD.

Health, armour, ammunition, reloads, abilities, and equipment communicate through the dog and nearby world. Temporary descriptions appear only when needed.

Why: attention belongs on the island. A compass preserves navigation and pack awareness without turning combat into dashboard reading.

Archived / procedural future

Authored spaces, shuffled carefully.

One recognizable island and centre come first. Proven modular regions can later randomize paths, cover, creatures, loot, and sightlines under validation rules.

Why: unconstrained procedural terrain creates unfair spawns and bad fights. Randomness should recombine good design, not replace it.

Archived / pack darkness

Leaving can be worth it.

Packed dogs see and survive better. Isolated dogs attract swarms and lose reliable information, but darkness hides valuable bounty.

Why: togetherness is meaningful only if separation remains a choice. Risk outside the pack creates scouting, rescue, and greed.

World / art

Compact occult-western heroes.

Small upright dog gunslingers cross red earth under moonlight, carrying improvised armour and supernatural charms against angular creatures of night.

Why: compact proportions read from an orthographic top-down camera; the occult western gives Terra Rossa an identity that supports firearms, scarcity, and darkness.

Technical / web

The browser sets the budget.

Three.js renders four players and a deliberately small creature population. Colyseus runs a measured 30 Hz simulation and synchronizes at a lower patch rate. Entity, effect, message, and memory caps begin in the first slice.

Why: web performance and network traffic cannot be bolted on later. Starting with 12–24 creatures and four players provides useful evidence without pretending the old horde scale is free.

Process / roadmap

Build evidence before content.

The old Pack Royale backlog is explicitly superseded. The active path is handshake, authoritative movement, a combat toy, a four-player free-for-all, PvPvE pressure, then browser polish.

Why: an LLM works best with bounded scope, while the human needs to understand each boundary. Every milestone produces one playable, explainable layer before the next is introduced.

The match

One map. No truce.

The first game asks whether creatures, scarcity, information, and one unpredictable opponent create a match worth replaying—without packs, progression trees, or sixteen-player infrastructure.

Spawn

Begin far apart, concealed by geography rather than immunity.

Scavenge

Spend ammunition on creatures and move toward better supplies.

Listen

Infer the opponent through gunfire, disturbed enemies, and traces.

Converge

Central loot and closing darkness narrow every safe route.

Survive

Choose when to engage; the last living player wins.

Make one unpredictable opponent matter before building sixteen players.

Still unresolved

Questions are part of the record.

Open decisions stay visible instead of quietly becoming assumptions. Prototypes and playtests should answer these—not confidence.

T4.7 / authoritative darkness 31 July 2026

The vignette is atmosphere, not security

The room now owns one visibility radius and uses it when deciding whether each viewer receives player, creature, projectile, and pickup coordinates. Walls still occlude inside that radius. This means deleting the CSS darkness cannot reveal data that never crossed the network.

Fully silent hidden fights felt unreadable, so gunfire and creature wind-ups produce a private eight-way compass bearing. The cue contains a category and direction but no position. For a junior developer, the lesson is to separate knowledge (server-filtered state) from mood (the client vignette).

Evidence: 158 automated checks cover range, authored wall occlusion, eliminated subjects, coarse bearings, schema adaptation, and room behaviour; type checking, linting, and the production client build pass.
T4.8 / closing night 31 July 2026

Pressure moves the player; it never moves their character

The safe rectangle contracts every two minutes toward the central ruin, where several approaches and pieces of cover remain useful. Outside damage escalates from a warning bite to lethal pressure, while visibility also narrows. No teleport or protected duel phase interrupts the continuous match.

The room publishes one clock, stage, boundary, visibility radius, and damage rate. Damage enters the same ordered queue as bullets, melee, and creatures, so simultaneous deaths and victory do not acquire a second set of rules. At twelve minutes the final stage damages everyone, providing an honest hard maximum.

Implementation lesson: model a shrinking zone as data plus one pure “outside” predicate. Rendering, warnings, damage, tests, and later tuning can then share the same facts without letting the browser decide who is safe.
T4.9 / production seed incident 31 July 2026

A playtest found a crash that unit-scale seeds missed

A hosted four-client run repeatedly froze at countdown tick two. Fly logs showed the actual cause: JavaScript XOR returns a signed 32-bit value, so a valid random room seed could become negative when salted for creature placement. The random generator then correctly rejected it and the process exited.

Round-derived seeds now pass through one tested unsigned normalizer for creature, pickup, and shotgun plans. The hosted harness also bounds cleanup and reports observed countdown values instead of hiding the original failure behind a hanging leave.

Lesson: deterministic randomness still needs boundary-value tests. A seed of 42 proves repeatability; it does not prove that every uint32 survives JavaScript bitwise operators.
T4.9 / interference telemetry 31 July 2026

Measure whether monsters decide the gunfight

The room now totals creature-to-player damage, player-to-creature damage, ammunition spent, and PvP deaths that occur while a living creature is within five metres. It records only the latest coarse encounter quadrant, not a route or exact coordinate. Match duration reuses the authoritative darkness clock.

The four-client harness emits the same bounded counters and the server writes one structured summary when a round ends. This is enough to compare tuning runs without adding an analytics service or collecting player identity.

Lesson: add the smallest counter that can disprove a balance claim. “Creatures felt unfair” becomes a question about damage share and pressured PvP deaths.
T4.9 / first measured tuning 31 July 2026

Sixteen creatures erased the opening gunfight

Two hosted four-client runs at 15 ms added latency plus jitter both ended after 264 simulation ticks—8.8 seconds. Creatures dealt 240 and 216 damage, players dealt zero damage back, and each match recorded a PvP death under nearby creature pressure. That is strong evidence that PvE decided the opening.

The comparison build changes data only: normal population falls from sixteen to eight (six swarmers, two spitters), evenly split across all four regions, and initial player exclusion grows from five to seven metres. Behaviour code remains untouched so the next hosted result has a clear cause.

Decision rule: creatures should create movement and opportunity, but a scripted player route must survive long enough to spend ammunition and engage another dog.
T4.9 / comparison result 31 July 2026

Less pressure helped; bots cannot answer “is it fun?”

Three post-tuning hosted runs lasted 336–339 ticks (about 11.2 seconds), compared with 264. They spent 7–12 rounds and finally damaged creatures for 24–72 health. Creature damage still reached 186–216 and one or two PvP deaths happened under pressure.

This proves the data change moved the right metrics, but the harness intentionally gives only one dog combat logic; the other three run routes and do not defend themselves. Further balance changes would tune around bad bots. The concrete next experiment is a four-human session where every player can kite, melee, and choose whether to spend ammunition on PvE.
